# 1.1 — Veritabanı temeli + kayıt/giriş

> Faz 1, adım 1.1'in çıktısı. İlk tablo (`users`), sqlc akışı, parola
> hash'leme, access token, kimlik middleware'i ve **API'nin istek/hata
> sözleşmesi** bu adımda kuruldu.

## 1. Şema ve veri erişimi

`db/migrations/00002_users.sql` — projenin ilk tablosu:

| Sütun           | Tip           | Not                                            |
| --------------- | ------------- | ---------------------------------------------- |
| `id`            | `uuid` PK     | `gen_random_uuid()` (Postgres 13+ çekirdeğinde) |
| `email`         | `text` UNIQUE | uygulama tarafında küçük harfe normalleştirilir |
| `password_hash` | `text`        | Argon2id PHC dizesi                             |
| `name`          | `text`        | 1–120 karakter (`CHECK`)                        |
| `created_at`    | `timestamptz` | `now()`                                         |

Kararlar:

- **Tablo adı `users`, `user` değil.** `user` SQL'de ayrılmış sözcük; her
  kullanımda `"user"` yazmak gerekirdi.
- **`CHECK (email = lower(email))` yok.** Go'nun `strings.ToLower`'ı ile
  Postgres'in `lower()`'ı her Unicode kod noktasında birebir aynı davranmak
  zorunda değil; ayrışan tek bir karakter geçerli bir kaydı 500'e çevirirdi.
  Normalleştirme tek yerde (uygulama), bütünlüğün son hakemi `UNIQUE`.
- **`updated_at` yok.** Bu fazda kullanıcı satırını güncelleyen akış yok;
  geldiğinde kendi migration'ıyla eklenecek (kullanılmayan altyapıyı
  taşımama kararının şema tarafındaki karşılığı).
- **Benzersizlik "önce SELECT et" ile değil, kısıtla.** İki istek aynı anda
  gelirse ikisi de "yok" görüp INSERT ederdi. Kod, Postgres'in `23505`
  hatasını `409 email_taken`'a çeviriyor (`internal/postgres/errors.go`).

**sqlc akışı:** `db/queries/*.sql` → `internal/store` (tamamı üretilmiş kod).
Sorgu ile şema uyuşmazsa hata çalışma zamanında değil `sqlc generate`
sırasında çıkıyor.

```bash
pnpm db:generate
```

sqlc **yerel olarak kurulmadı**, resmi imajla (`sqlc/sqlc:1.31.1`)
çalışıyor: sqlc'nin Postgres ayrıştırıcısı cgo istiyor, bu makinede gcc yok.
**Üretilen kod repoya commit ediliyor** — CI ve klonlayan herkes sqlc olmadan
derleyebilsin.

## 2. Parola: Argon2id

`internal/auth/password.go`. Saklanan biçim PHC dizesi:

```
$argon2id$v=19$m=19456,t=2,p=1$<tuz-b64>$<hash-b64>
```

| Parametre | Değer         | Gerekçe                                |
| --------- | ------------- | -------------------------------------- |
| `m`       | 19456 (19MiB) | OWASP'ın Argon2id için minimum önerisi  |
| `t`       | 2             | aynı öneri                             |
| `p`       | 1             |                                        |
| tuz       | 16 byte       | `crypto/rand`                          |
| çıktı     | 32 byte       |                                        |

- **Neden bcrypt değil:** bcrypt parolayı **72 byte'ta sessizce kırpar** —
  "…72 byte" ile "…72 byte + fazlası" aynı hesaba girer. canny-mini bcrypt
  kullanıyor; burada sınır hiç doğmuyor. Argon2id ayrıca OWASP'ın güncel
  önerisi ve bellek-zor. **Ek bağımlılık yok:** ikisi de
  `golang.org/x/crypto` modülünden.
- **Parametreler hash'in içinde.** Maliyet ileride artırıldığında eski
  kayıtlar kendi parametreleriyle doğrulanmaya devam ediyor; kimsenin
  parolası geçersizleşmiyor.
- **Karşılaştırma `subtle.ConstantTimeCompare` ile** — byte byte
  karşılaştırma kaç byte'ın tuttuğunu süreyle sızdırır.
- **Sınırlar:** en az 8 karakter, en fazla **1024 byte**. Üst sınır Argon2'nin
  değil, kaynak tüketiminin sınırı. Kompozisyon kuralı (büyük harf/simge)
  bilinçli olarak YOK (NIST SP 800-63B).
- **Bozuk/kötü niyetli bir hash satırı süreci belleksiz bırakamaz:**
  çözümlenen parametreler makul aralık dışıysa (`m > 1 GiB` gibi) hash
  geçersiz sayılıyor.

## 3. Access token

`internal/auth/token.go` — `golang-jwt/jwt/v5`, HS256.

Claim'ler: `iss=uptime-mini`, `aud=uptime-mini-api`, `sub=<user uuid>`,
`jti=<uuid>`, `iat`, `nbf`, `exp`, `token_use=access`.

Doğrulamada açıkça istenenler:

- `jwt.WithValidMethods(["HS256"])` — **algoritma karışıklığı (alg
  confusion)** saldırısının cevabı: `"alg":"none"` veya asimetrik bir
  algoritmayla imza atlatma denemesi doğrulama başlamadan biter.
- `WithIssuer` + `WithAudience` + `WithExpirationRequired()` + `WithIssuedAt()`.
- **Saat toleransı 0** — tolerans, süresi dolmuş token'ın kabul edildiği bir
  penceredir.
- `token_use` alanı: Faz 1.2'nin refresh token'ı access token yerine
  kullanılamasın. (Sırlar da ayrı; tek savunmaya güvenilmiyor.)
- **`jti` her token'da var:** aynı kullanıcı için aynı saniyede üretilen iki
  token birebir aynı çıkamaz — canny-mini'de refresh token'da yaşanan gerçek
  hata. Tekil iptal (1.2) de bu kimliğe dayanacak.

Ömür: `JWT_ACCESS_TTL`, varsayılan **15 dakika**, üst sınır 1 saat.

**Kimlik `context` ile taşınıyor** (`internal/auth/identity.go`): anahtar
dışa kapalı boş bir struct tipi (`identityContextKey{}`), ham string değil —
başka bir paketin aynı adı kullanıp değeri ezmesi veya kimlik taklidi
derleyici seviyesinde imkânsız. Panikleyen bir `MustIdentity` bilinçli olarak
yok.

## 4. İmzalama anahtarları (`.env`)

`.env.example`'daki `__GENERATE_ME__` değerleri **hiçbir ortamda** imzalama
anahtarı olarak kullanılmıyor. Davranış:

| Durum                                          | Sonuç                                              |
| ---------------------------------------------- | -------------------------------------------------- |
| Geçerli anahtar verilmiş (≥32 karakter)        | olduğu gibi kullanılır                              |
| Placeholder/eksik + `APP_ENV=development\|test` | **geçici rastgele anahtar üretilir**, uyarı loglanır |
| Placeholder/eksik + `APP_ENV=production` veya boş/bilinmeyen | **boot reddedilir**                    |
| access == refresh                              | **boot reddedilir**                                 |

Gerekçe: "klonlayan herkes `cp .env.example .env && docker compose up` ile
çalıştırabilmeli" sözü ile "bilinen imzalama anahtarı = tam kimlik taklidi"
kuralının ikisi de korunuyor. Bedeli (api yeniden başlayınca oturumların
düşmesi) uyarı metninde açıkça yazıyor:

```
JWT_ACCESS_SECRET için geçici imzalama anahtarı üretildi — api yeniden
başlarsa tüm oturumlar düşer; kalıcı olması için .env'e `openssl rand -hex 32`
çıktısını yaz.
```

`APP_ENV`'in **bilinmeyen bir değeri artık hata** (`prod`, `staging` …):
sessizce development'a düşmek, üretimde fark edilmeyen bir yapılandırma
hatasıdır.

## 5. API sözleşmesi

Ürün uçları `/v1` altında; `/health` ve `/ready` **sürümsüz** kalıyor
(altyapı uçları, orkestratör API sürümlendiğinde yol değiştirmemeli).

### `POST /v1/auth/register` → `201`

```json
{ "email": "ali@example.com", "password": "cok-gizli-parola", "name": "Ali Veli" }
```

```json
{
  "user": { "id": "…", "email": "ali@example.com", "name": "Ali Veli", "createdAt": "…" },
  "accessToken": "eyJhbGciOiJIUzI1NiIs…",
  "expiresIn": 900
}
```

### `POST /v1/auth/login` → `200`

Aynı cevap gövdesi. `GET /v1/me` (Bearer token) → `{"user": {…}}`.

**Parola hash'i hiçbir cevapta görünmez:** `store.User` doğrudan
serileştirilmiyor, ayrı bir `userResponse` tipi var (şemaya eklenen bir
sütun kazara API'ye düşemesin). Testi de var.

### Hata gövdesi — her hata aynı zarfta

```json
{
  "error": {
    "code": "validation_failed",
    "message": "gövde doğrulanamadı",
    "fields": [{ "field": "email", "message": "geçerli bir e-posta adresi olmalı" }],
    "requestId": "…"
  }
}
```

| Kod                      | HTTP | Ne zaman                                     |
| ------------------------ | ---- | -------------------------------------------- |
| `invalid_json`           | 400  | bozuk/boş gövde, tanımsız alan, tip uyuşmazlığı |
| `unsupported_media_type` | 415  | Content-Type application/json değil           |
| `payload_too_large`      | 413  | gövde > 64 KiB                                |
| `validation_failed`      | 422  | JSON geçerli, alanlar değil                   |
| `invalid_credentials`    | 401  | giriş başarısız (tek ve aynı cevap)           |
| `email_taken`            | 409  | e-posta zaten kayıtlı                         |
| `unauthorized`           | 401  | token yok/geçersiz                            |
| `token_expired`          | 401  | token süresi dolmuş (istemci tazeleyebilir)   |
| `not_found`              | 404  | bilinmeyen uç                                 |
| `method_not_allowed`     | 405  | uç var, metot yok                             |
| `internal_error`         | 500  | beklenmeyen hata (ayrıntı yalnızca logda)     |

`code` var çünkü istemci karar verirken insan metnine bakmamalı; `requestId`
var çünkü kullanıcının gördüğü hata ile sunucu logu birbirine bağlanabilmeli.

Gövde kuralları (`decodeJSON`): Content-Type zorunlu · 64 KiB sınırı ·
**tanımsız alanlar reddedilir** (`passwordd` yazan istemci sessizce boş
parolayla devam etmesin) · gövdede tek bir JSON değeri olmalı.

### Kullanıcı sızdırmama

- **Giriş:** "e-posta kayıtlı değil" ile "parola yanlış" **aynı gövdeyi**
  döndürüyor; kullanıcı bulunamadığında da bir Argon2 hash'i hesaplanıyor
  (`VerifyDummy`) ki cevap süresi farkı kayıtlı e-postaları ele vermesin.
  Girişte alan doğrulama ayrıntısı da verilmiyor.
- **Kayıt:** 409 ile bir e-postanın kayıtlı olduğunu ele veriyor. Bunu
  gizlemenin tek gerçek yolu "e-posta ile onay" akışı; bu projede dış e-posta
  servisi yok (docs/0.0-constraints.md §2). **Bilinçli kabul.**
